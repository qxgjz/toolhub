💡 JWT Token 结构说明

JWT (JSON Web Token) 由三部分组成，用点号 (.) 分隔：

  • Header（头部）：包含 Token 类型和签名算法，如 {"alg":"HS256","typ":"JWT"}
  • Payload（载荷）：包含声明（Claims），如用户ID、过期时间等。注意：Payload 仅做 Base64 编码，非加密，不要放置敏感数据
  • Signature（签名）：使用 Header 指定的算法和密钥对 Header.Payload 进行签名，用于验证 Token 完整性

🔧 常见使用场景

  • 调试 API 认证：开发中查看 Token 内的 Claims 信息，确认签发内容正确
  • 检查过期时间：快速确认 Token 是否过期或即将过期
  • 排查权限问题：检查 Token 中的角色/权限声明是否正确
  • SSO/OAuth 调试：解析身份令牌，查看用户信息映射
  • 微服务间认证：验证服务间传递的 Token 内容

❓ 常见问题解答

Q: JWT解码会泄露敏感信息吗？

A: 不会。本工具完全在浏览器本地解码，不会将Token上传到服务器。但请注意JWT的Payload是Base64编码而非加密，不要在Payload中放置敏感数据。

Q: 这个工具能验证JWT签名吗？

A: 本工具仅做解码展示，不验证签名。签名验证需要密钥（HS256）或公钥（RS256），出于安全考虑不在浏览器中处理。

Q: 支持哪些JWT算法？

A: 支持所有标准JWT算法（HS256/HS384/HS512/RS256/RS384/RS512/ES256/ES384/ES512/PS256等）的解码。签名验证需要对应密钥。

Q: JWT和Session有什么区别？

A: JWT是无状态的，包含用户信息直接编码在Token中；Session是有状态的，信息存在服务端。JWT适合微服务和跨域场景，Session适合单体应用。
